# Use Cases для CRM системы ресторана

## Актеры системы

- **Администратор зала** — управляет залом, столами, бронированиями и мероприятиями
- **Официант** — принимает заказы, обслуживает столы
- **Повар** — обрабатывает заказы на кухне
- **Бармен** — обрабатывает заказы на напитки
- **Клиент** — использует мобильное приложение для заказов и бронирований

***

## Use Case 1: Управление расположением столов

**Актер:** Администратор зала

**Описание:** Администратор может просматривать план зала и изменять расположение столов

**Основной сценарий:**

1. Администратор открывает раздел "План зала"
2. Система отображает текущее расположение столов
3. Администратор перемещает столы drag-and-drop
4. Администратор сохраняет изменения
5. Система обновляет план зала

***

## Use Case 2: Бронирование стола

**Актер:** Администратор зала, Официант

**Описание:** Сотрудник бронирует стол для гостя на определенное время

**Основной сценарий:**

1. Сотрудник выбирает дату и время бронирования
2. Система показывает свободные столы
3. Сотрудник выбирает стол и вводит данные гостя (имя, телефон, количество персон)
4. Система создает бронь
5. Система отправляет подтверждение гостю

**Альтернативный сценарий:**

- Если все столы заняты, система предлагает ближайшее свободное время

***

## Use Case 3: Оформление заказа за столом

**Актер:** Официант

**Описание:** Официант создает заказ для стола в зале

**Основной сценарий:**

1. Официант выбирает стол
2. Официант добавляет блюда и напитки из меню
3. Официант указывает комментарии к блюдам (если есть)
4. Официант отправляет заказ
5. Система разделяет заказ: блюда → поварам, напитки → барменам

***

## Use Case 4: Бронирование ресторана под мероприятие

**Актер:** Администратор зала

**Описание:** Администратор бронирует весь ресторан для проведения мероприятия

**Основной сценарий:**

1. Администратор выбирает дату и время мероприятия
2. Система проверяет доступность ресторана
3. Администратор вводит данные клиента и детали мероприятия
4. Администратор блокирует все столы на выбранное время
5. Система создает бронь мероприятия

***

## Use Case 5: Обработка заказа поваром

**Актер:** Повар

**Описание:** Повар видит новые заказы, берет их в работу и завершает

**Основной сценарий:**

1. Повар открывает список новых заказов
2. Система отображает заказы со статусом "Новый"
3. Повар выбирает заказ и переводит его в статус "В работе"
4. После приготовления повар переводит заказ в статус "Готово"
5. Система уведомляет официанта о готовности блюда

***

## Use Case 6: Обработка заказа барменом

**Актер:** Бармен

**Описание:** Бармен видит новые заказы на напитки, берет их в работу и завершает

**Основной сценарий:**

1. Бармен открывает список новых заказов на напитки
2. Система отображает заказы со статусом "Новый"
3. Бармен выбирает заказ и переводит его в статус "В работе"
4. После приготовления бармен переводит заказ в статус "Готово"
5. Система уведомляет официанта о готовности напитков

***

## Use Case 7: Управление меню

**Актер:** Администратор зала

**Описание:** Администратор добавляет, редактирует и удаляет блюда в меню

**Основной сценарий (добавление):**

1. Администратор открывает раздел "Меню"
2. Администратор нажимает "Добавить блюдо"
3. Администратор вводит название, описание, цену, категорию и загружает фото
4. Система сохраняет новое блюдо
5. Блюдо появляется в меню

**Альтернативный сценарий (редактирование):**

- Администратор выбирает существующее блюдо, изменяет данные и сохраняет

**Альтернативный сценарий (удаление):**

- Администратор выбирает блюдо и удаляет его из меню

***

## Use Case 8: Просмотр аналитики

**Актер:** Администратор зала

**Описание:** Администратор просматривает статистику работы ресторана

**Основной сценарий:**

1. Администратор открывает раздел "Аналитика"
2. Администратор выбирает период (день, неделя, месяц)
3. Система отображает ключевые метрики:
    - Выручка за период
    - Количество заказов
    - Средний чек
    - Популярные блюда
    - Загруженность столов

***

## Use Case 9: Регистрация клиента (мобильное приложение)

**Актер:** Клиент

**Описание:** Клиент создает учетную запись в мобильном приложении

**Основной сценарий:**

1. Клиент открывает приложение
2. Клиент нажимает "Зарегистрироваться"
3. Клиент вводит имя, телефон, email и пароль
4. Система создает аккаунт и авторизует клиента

***

## Use Case 10: Авторизация клиента (мобильное приложение)

**Актер:** Клиент

**Описание:** Клиент входит в свой аккаунт

**Основной сценарий:**

1. Клиент открывает приложение
2. Клиент вводит телефон/email и пароль
3. Система проверяет данные
4. Система авторизует клиента и открывает главный экран

***

## Use Case 11: Просмотр меню (мобильное приложение)

**Актер:** Клиент

**Описание:** Клиент просматривает актуальное меню ресторана

**Основной сценарий:**

1. Клиент открывает раздел "Меню"
2. Система отображает категории блюд
3. Клиент выбирает категорию
4. Система показывает блюда с фото, описанием и ценой
5. Клиент может посмотреть детали любого блюда

***

## Use Case 12: Заказ доставки (мобильное приложение)

**Актер:** Клиент

**Описание:** Клиент оформляет заказ с доставкой на дом

**Основной сценарий:**

1. Клиент добавляет блюда в корзину
2. Клиент переходит к оформлению заказа
3. Клиент вводит адрес доставки
4. Клиент выбирает способ оплаты (онлайн/при получении)
5. Клиент подтверждает заказ
6. Система создает заказ и отправляет его на кухню
7. Система показывает статус заказа клиенту

***

## Use Case 13: Закрытие счета за столом

**Актер:** Официант

**Описание:** Официант формирует и закрывает счет для стола

**Основной сценарий:**

1. Официант выбирает стол
2. Система отображает все заказы стола
3. Официант формирует счет
4. Официант выбирает способ оплаты (наличные/карта)
5. Официант закрывает счет
6. Система освобождает стол

***

## Use Case 14: Отмена бронирования

**Актер:** Администратор зала, Официант

**Описание:** Сотрудник отменяет существующее бронирование

**Основной сценарий:**

1. Сотрудник открывает список бронирований
2. Сотрудник выбирает нужное бронирование
3. Сотрудник нажимает "Отменить бронь"
4. Система запрашивает подтверждение
5. Сотрудник подтверждает отмену
6. Система удаляет бронь и освобождает стол
7. Система отправляет уведомление гостю

***

## Use Case 15: Просмотр истории заказов (мобильное приложение)

**Актер:** Клиент

**Описание:** Клиент просматривает свои прошлые заказы

**Основной сценарий:**

1. Клиент открывает раздел "Мои заказы"
2. Система отображает список заказов клиента
3. Клиент выбирает заказ
4. Система показывает детали заказа (блюда, сумма, дата, статус)
5. Клиент может повторить заказ одной кнопкой
